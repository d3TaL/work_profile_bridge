# Изменения

## 0.1.1-recovered-tls — 2026-10-17

Проект воссоздан из переписки после очистки среды. Восстановлены Kotlin/Compose каркас, доменная валидация и маршрутизация, локальный запуск и profile diagnostics. Добавлен TLS 1.3 probe с pin, временным токеном, AndroidKeyStore EC identity и негативными TLS-тестами. Постоянное сопряжение и передача URL остаются следующими этапами. Старый APK signing key утрачен.
# 0.1.2-diagnostics (в работе)

- Структурированные стадии и безопасные причины отказов клиента/listener,
  отдельные pin/certificate, TCP, TLS и fixed ACK события.
- Локальный pinned TLS self-check; явное закрытие сокетов при отмене.
- Ограниченный журнал в памяти, предварительный просмотр и FileProvider export.
- Видимый монотонный TTL; существующая TLS identity не удаляется при неверных датах.
- GitHub Actions сохраняет APK, SHA-256, commit/run ID и отчёты на 14 дней.
- JVM: 23 теста PASS; Android-сборка ожидает SDK/запуска CI.
# 0.1.3-key-diagnostics

- По отчёту устройства: пять self-check попыток проходят TCP и падают на
  handshake до peer validation; точная причина остаётся неизвестной.
- Добавлена sign/verify проверка существующего EC ключа с синтетическим challenge.
- Диагностика выбора ключа/доступа к цепочке и безопасная категоризация cause chain.
- Не изменены pin, TLS 1.3, штатный provider и существующая identity.
# 0.1.4-keystore-tls

- Добавлено разрешение DIGEST_NONE для нового диагностического EC ключа:
  upstream Conscrypt использует NONEwithECDSA при TLS signing opaque EC keys.
- Версионированный alias v2; прежний v1 не удаляется и не перезаписывается.
- Перед подготовкой TLS проверяется raw ECDSA sign/verify на синтетических данных.
- Успех на устройстве ещё не подтверждён; межпрофильный TCP исследуется отдельно.
# 0.1.5-clipboard

- TLS-поля поддерживают обычное выделение текста; убран password input.
- Явные кнопки копирования кода сессии и введённого кода, вставка текста.
- Clipboard запись помечена sensitive; чтение только по нажатию пользователя,
  без URI/Intent coercion, с ограничением длины.
# 0.1.6-cross-profile-link

- Экспериментальная передача проверенной HTTPS-ссылки через новый explicit
  ACTION_SEND в свою копию посредством CrossProfileApps.startActivity.
- INTERACT_ACROSS_PROFILES запрашивается через штатные настройки по действию
  пользователя; перед каждой передачей проверяются актуальные доступ и target.
- Получатель одинаково валидирует cold/warm Intent и URL, ничего не запускает
  автоматически. Отказ доступа и UNKNOWN_OUTCOME различаются; повторов нет.
- Успех startMainActivity не выдаётся за право передачи payload. Secure Folder
  поддерживается только если сам API возвращает копию и разрешает операцию.
# 0.1.7-store-links

- Приём HTTPS Ozon/Wildberries через ACTION_VIEW и текста «Поделиться» с одним
  поддерживаемым адресом; исходные query/fragment не переписываются.
- Защищённый signature-permission вход между копиями для автооткрытия магазина
  в профиле получателя после ручной отправки. Переключатель получателя default off.
- Только точные shop hosts и product/root paths, фиксированные пакеты; наличие
  магазина в основном профиле не требуется. Bank/account/payment auto-open нет.
- Одна попытка в RESUMED, TTL 30 секунд, bounded memory replay guard,
  без восстановления Intent после пересоздания, автоматических повторов нет.
