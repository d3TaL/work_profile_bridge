# Архитектура

## Границы ответственности

| Область | Ответственность | Не должна делать |
| --- | --- | --- |
| UI / ViewModel | Выбор, согласие, lifecycle state, безопасный отчёт | TLS, parsing и PackageManager на main thread |
| Routing core | Валидация, правила домен/путь/пакет, неоднозначность | Запускать Android Activity |
| Transport adapter | Capability probe, соединение/отправка в рамках разрешений | Определять доверие по факту localhost |
| Pairing / Trust | Идентичности, подтверждение, отзыв, защита credentials | Молча принимать сертификат peer |
| Delivery | TTL, IDs, дедупликация, статусы | Считать ACK доказательством открытия банка |
| Android platform | Keystore, intent sanitizer, profile API, package-scoped launch | Переносить произвольный исходный Intent |

Это логические границы. Не создавать шесть Gradle-модулей заранее. Для первого этапа достаточно JVM `core` и Android `app`, если существующий проект не диктует иное.

## Транспорт выбирается по capability

Work profile: исследовать CrossProfileApps, реальные allowlists/разрешения и cross-profile intent filters, управляемые DPC. Launcher-переход в свою копию не равен доставке payload или праву запускать чужой пакет. Если требуется profile owner, явно описать это; не пытаться занять роль на уже управляемом устройстве.

Secure Folder: отдельный adapter с UNKNOWN до подтверждения публичного разрешённого пути. Обычный SDK не считать эквивалентом привилегированного Samsung Knox SDK. Любые лицензии и enterprise requirements выяснить до включения в продукт.

Loopback: диагностический/условный adapter для реально доступных конфигураций. Android 17 блокирует межпрофильный loopback по умолчанию независимо от targetSdk. Проверить можно, обещать работоспособность нельзя. Не переходить на LAN bind, cloud или произвольные порты как на скрытый fallback.

Необязательный Shizuku adapter — отдельное исследование полномочий и пользовательской авторизации; не обязательная часть MVP и не доказанный путь через Secure Folder. Не строить shell-команды из URI.

Если когда-либо подтвердится только исходящее соединение из контейнера, обратные сообщения внутри этого аутентифицированного соединения можно исследовать отдельно. Сейчас успешного соединения нет; такую схему не считать готовым решением.

## Будущая доставка

Логическая машина: CREATED → VALIDATED → SENT → ACCEPTED → AWAITING_USER → LAUNCH_REQUESTED. Терминальные состояния: REJECTED, EXPIRED, CANCELLED; при обрыве после отправки — UNKNOWN_OUTCOME. LAUNCH_REQUESTED не означает успешную операцию внутри банка.

Сообщение должно иметь protocol version, random message ID, назначение доверенной пары/пространства, разрешённый target, исходный URL и ограниченный TTL. Точную сериализацию определить отдельным ADR после выбора транспорта. Ограничить frame size до выделения памяти. Получатель проверяет всё независимо от отправителя.

В пределах живого процесса TTL считать монотонными часами. После перезапуска не продлевать срок молча; для дисковой очереди определить поведение при reboot/изменении wall clock или сбрасывать ожидающие запросы. Отмена не гарантирует отзыв уже начатого действия.

До полноценного протокола никакой передачи URL в fixed ping и автоматического переключения транспорта после неизвестного результата.
