# Состояние проекта и доказательства

## Цель владельца

Открывать ссылку из основного пространства в установленном внутри целевого пространства Ozon или банковском приложении. У владельца есть и work profile, и Secure Folder. Порты между двумя копиями были первоначальной идеей, а не обязательным требованием.

## Что известно по переписке

| Факт | Статус |
| --- | --- |
| Основное устройство Android 17 / One UI 9 | Со слов владельца; модель и fingerprint не получены |
| Парк Android 11–17, One UI 8.5/9 | Целевой диапазон, не матрица пройденных тестов |

| Secure Folder: успешный TLS изнутри наружу | НЕ подтверждён; владелец уточнил, что соединения нет в обе стороны |
| Secure Folder: одновременная видимость обеих копий | Не проверено; владелец пока не мог выполнить |
| Work profile: TLS-проверка не прошла в обе стороны | Последнее подтверждённое наблюдение |
| Work profile: обе копии одновременно на экране, точный возраст кодов | Не установлено |
| Работающий межпрофильный транспорт | Не доказан |
| Доставка реальной ссылки в Ozon/банк | Не реализована в описанной диагностической версии |

Не интерпретировать список CrossProfileApps как сетевое обнаружение. Не называть отказ TLS доказательством успешного TCP без данных этапа.

## Предыдущая диагностическая версия

В переписке описана 0.1.1-recovered-tls, Kotlin/Compose, minSdk 30, compile/target 37. В ней заявлены HTTPS parser, routing core, локальный выбор обработчика, CrossProfileApps диагностика и фиксированный TLS 1.3 ping по 127.0.0.1. URL по TLS не передавался.

Временный код PLB2 содержал порт, SHA-256 сертификата и случайный 256-битный токен. Сессия: до 120 секунд и 32 принятых соединений; I/O timeouts порядка двух секунд. Ключ Android — AndroidKeyStore EC P-256. Это не постоянное сопряжение и не mTLS.

По показанному ранее коду SSLHandshakeException и IllegalArgumentException превращались в TLS_REJECTED; общий IOException — в UNAVAILABLE. ViewModel объединял NOT_PERMITTED с UNAVAILABLE. Поэтому пользовательские сообщения недостаточны для установления причины. В реальном checkout это надо проверить повторно.

Предыдущий ассистент сообщил о 18 JVM-тестах, успешных Debug/Release/lint, strict dependency verification и 16 KiB alignment. Это историческое сообщение, не новая проверка и не испытание на Samsung. Не переносить результаты в новый VALIDATION как выполненные текущим агентом.

Исходники и tooling прежней рабочей среды были удалены автоматической очисткой. Этот комплект не содержит старого проекта. Использовать предоставленный владельцем архив/репозиторий, если он есть; иначе новая реализация должна быть явно обозначена. Сохранность прежнего debug signing key неизвестна.

## Данные, которые ещё нужны

Получать только по необходимости: модель, API/release/build, security patch, точная версия APK и направление теста, тип/DPC рабочего профиля, возраст кода, состояния окон/блокировки/VPN, структурированная причина с обеих сторон. Не требовать реальные банковские ссылки или полный неотфильтрованный logcat.
