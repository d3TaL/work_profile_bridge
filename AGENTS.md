## Рабочий цикл владельца

После изменений: проверка, коммит и push в `d3TaL/work_profile_bridge`, ожидание
GitHub Actions, скачивание APK и SHA-256 в `/storage/emulated/0/Download/artifacts`,
затем короткий сценарий теста владельцу. Автор и коммитер — `d3TaL`
(`<85562612+d3TaL@users.noreply.github.com>`), без упоминаний ассистента и
Co-authored-by. Использовать переменные окружения git, не менять git config.

Один APK устанавливается в основной профиль, рабочий профиль и Samsung Secure Folder. Android 11+ (minSdk 30), основное устройство владельца Android 17 / One UI 9. Не считать Secure Folder обычным work profile.

Проект восстановлен из переписки после очистки среды. Старые контрольные суммы и результаты сборок не выдавать за результаты этой версии. Текущие результаты записывать в docs/VALIDATION.md.

1. Не передавать банковские URL через диагностический протокол. Он принимает только фиксированный ping, без package, URL, Intent и команд.
2. Разделять достижимость сети, аутентификацию TLS и запуск Android Activity. Успех ping не подтверждает переход в банк.
3. Не обходить блокировку Knox, не требовать root, Accessibility, overlay или смену profile owner.
4. Полученные Intent не перенаправлять. Извлекать только ограниченный текст через IntentSanitizer; одинаково проверять onCreate/onNewIntent. Локальный запуск только новым ACTION_VIEW в выбранный пакет после жеста пользователя.
5. Не записывать URL, токены и ключи в логи, saved state, backup или аналитику. Чувствительные toString должны быть redacted.
6. TLS только через штатный провайдер, без TrustAll, отключения проверки сертификата или plaintext fallback. Ключ Android — в AndroidKeyStore; I/O и генерация ключей вне main thread.
7. Сравнивать SHA-256 сертификата с pin из вручную перенесённого кода. Код включает случайный 256-битный токен и ограничен сессией, это ещё не постоянное сопряжение.
8. Не гарантировать фоновые Activity или постоянный listener. Не выбирать фиктивный FGS type. При недоступном контейнере показывать наблюдаемый отказ.
9. До полного протокола доставки не реализовывать автоматические повторы банковских действий. Постоянная доставка требует дедупликации, TTL и состояния UNKNOWN_OUTCOME.
10. Версии зависимостей фиксировать, release собирать с R8, lint не подавлять общим baseline. Тесты и сборку запускать после содержательных изменений, не повторять без причины.
