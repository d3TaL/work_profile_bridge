# Безопасность

Активы: одноразовые URL/токены, привязка профиля к пакету, идентичность peer. Угрозы: локальный ложный listener, подмена кода сопряжения, Intent injection, replay, утечки через backup/logs/уведомления. Root и скомпрометированная ОС вне гарантируемой модели.

Меры текущей версии: only-loopback TLS 1.3, pin из вручную выбранного кода, проверка validity сертификата, 256-bit session token внутри TLS, bounded чтение/число подключений, redacted toString, AndroidKeyStore для signing key, без логов секретов. Ключ не требует биометрии для каждого handshake; это ограниченный диагностический ключ, а не право совершать банковские действия. Hardware-backed размещение не обещается и не измерено.

Trust manager отвергает другой сертификат; не использует TrustAll и не применяется к произвольному HTTPS-интернету. Это специализированный канал с явно выбранным peer, где идентичность задаёт pin, а не DNS/публичный CA. Сервер не требует client certificate; доступ к фиксированному ping ограничен bearer token. Это не mTLS и не постоянное двухстороннее доверие.

Экспортирован только launcher/импорт текста. Его данные недоверенные и не запускают приложение автоматически. Входящие Intent санитизируются, caller extras не используются для авторизации. Нет экспортированного сервиса с командами.

URL хранится в памяти, очищается onStop, не кладётся в SavedStateHandle/backup. Backup и device transfer исключены. FLAG_SECURE не является гарантией на скомпрометированной ОС. Приложение не контролирует журналы системных/целевых приложений.

До банковского использования нужны постоянное сопряжение/отзыв, политика пакетов/сертификатов, протокол URL, TTL/дедупликация, безопасные уведомления и отдельный review. Успешные тесты TLS не являются независимым аудитом.
