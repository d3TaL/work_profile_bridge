# Реестр доменов приложений

## Secure Folder через Sharesheet — 0.2.2

Владелец подтвердил доставку через системное «Поделиться» в Bridge внутри Knox
на 0.2.1; автооткрытия не было, поскольку public SEND допускал только ручной запуск.
Добавлен независимый auto-open-share=false по умолчанию, без role defaults.
Включать внутри целевого контейнера. Это разрешение локально открывать
поддерживаемые адреса из любого ACTION_SEND: не аутентификация отправителя,
не подтверждение реального выбора системного chooser и не Knox permission.
VIEW этим режимом не разрешается. Если share opt-in включён, public SEND
никогда не автопересылается, даже при auto-forward=true. Локальный share opt-in
независим от защищённого auto-open. Protected endpoint не может использовать
его для обхода ticket/TTL/replay. URL по-прежнему sanitizer + SafeLink + registry,
новый package-scoped VIEW, receiver query вне main, RESUMED, no retries.
На rotation/process death pending не восстанавливается. Compact применим.

## Изменение 0.2.1

Ниже исторические defaults 0.2.0. С 0.2.1 роль определяется публичными
UserManager.isSystemUser/isManagedProfile. OTHER/UNKNOWN не автоконфигурируются;
это не распознавание Knox или гарантированная идентификация Secure Folder.
При первой настройке role-defaults-v1 main получает auto-forward=true,
managed auto-open=true. Изменения пользователя сохраняют manual markers и
не перезаписываются на последующих стартах. Старая 0.2.0 этих markers не имела:
при миграции её старый false считается ещё не настроенным default.
Compact остаётся false. В основной при отсутствии сохранённой цели выбирается
только единственная доступная CrossProfileApps цель, сохраняется её serial.
Автоматика по-прежнему требует allowlist/consent Android.

Compact теперь использует translucent dialog без dim/preview/анимации окна;
Compose UI не создаётся на pending auto-forward/auto-open, только при отказе
или ручном режиме. RESUMED и TTL проверки сохраняются. Это уменьшение мерцания,
не гарантия отсутствия Android splash/профильного перехода или разрешения BAL.
При холодном старте manifest transit тема подавляет preview; launcher в onCreate
выбирает обычную тему. Warm full-screen Activity не меняет тему автоматически.

## Автоматизация — opt-in

Три независимых boolean, все false по умолчанию: auto-forward, auto-open,
compact. Настройки не резервируются. Основная копия хранит выбранный target
как UserManager serial (не порядковый индекс): исчезнувший профиль не заменяется
другим автоматически. Перед отправкой target и доступ проверяются снова.

Автопередача исполняется только после RESUMED и независимой проверки входящей
поддерживаемой ссылки на обычном входе. Защищённый получатель не пересылает её
обратно даже с включённой автопередачей. Pending в памяти, потребляется до вызова,
очищается onStop/редактированием и не восстанавливается после rotation/process death.
Нет ACK или повторов. Новый входящий Intent — новая попытка, не глобальная дедупликация.

Компактный режим выбирает dialog Activity для входящего SEND/VIEW при cold launch,
около 90% ширины и 65% высоты доступного окна. Launcher остаётся обычным экраном.
У уже открытого full-screen Activity тёплый Intent не меняет тему до нового
создания. В обеих копиях compact включается отдельно. Окно finish после
SUBMITTED_UNKNOWN_OUTCOME или успешного startActivity, что не доказывает доставку
и отображение Ozon. При отказе или ручном режиме остаётся UI с ручными действиями.
Это обычная видимая Activity, не невидимый background service/FGS. Балансировка
окон, анимация и разрешение запуска на Samsung требуют испытания на устройстве.
